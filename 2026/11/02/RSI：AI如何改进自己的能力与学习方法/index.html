AI 可以从失败中总结经验，但如果负责总结经验的流程本身不够好，谁来改进这套流程？RSI（Recursive Self-Improvement，递归自我改进）研究的就是这个问题：系统根据反馈提升能力，再用得到的能力改进后续的学习和升级过程。

理解 RSI，需要抓住一条主线：从记住有效经验，到改进学习方法，再到让下一代更会继续改进自己。

一、什么是递归自我改进

假设一个 AI 在《我的世界》中接到任务：采集圆石。它反复空手挖石头，却始终没有得到需要的材料。经过检查，它发现应该先准备镐，再开采石头。

如果这次任务结束后，它又忘记了这个前置条件，那么改善的只是当前这次表现。如果它将经验写进技能库，下一次任务也能使用，改进就被保留下来了。

但经验积累还会带来新的问题：技能库越来越长，规则开始重复、冲突，查找和执行也变得困难。

于是，系统调整了维护技能库的方法：以后新增规则前，先检查已有内容，合并重复项，明确适用条件，再验证修改效果。这套新方法会用于之后的每一次学习。

这里就出现了递归：系统改进了自己的能力，也改进了产生这些能力的方法；改进后的方法，又参与下一轮改进。

因此，判断一个系统是否具有递归特征，关键在于后续的改进过程有没有继承并使用新的改进机制。

二、RSI 的三个层级

按照改进深入的程度，可以用弱、中、强三个层级来理解 RSI。这个分法用于说明能力差异，并非统一的行业标准；研究中也有按系统自主程度进一步细分的方式。RSI 的自治能力分级与发展路线

1. 弱层级：让有效经验留下来

系统能根据反馈修改提示词、记忆、技能或模型参数，并在后续任务中复用有效结果。

例如，Agent 将“采集圆石前先准备镐”写进技能库，以后遇到相同问题就不再从头摸索。

这一层的变化发生在系统的知识和行为上。至于如何发现错误、如何修改技能、如何判断修改有效，仍然可以遵循人预先设计好的固定流程。

更严格地说，这属于持久化自我改进，是递归自我改进的基础。

2. 中等层级：连学习方法也能改进

系统开始修改负责产生改进的机制，包括如何分析失败、组织数据、更新技能，以及安排模型训练。

例如，原来的学习方法是“每次失败就追加一条规则”，后来改成“先归纳原因、合并重复规则，再补充新规则”。这次改变会影响后续所有技能更新。

这一层的变化发生在学习过程上。系统已经能够改进自己的改进方法，但仍可能只在预设的任务、组件和评价方式内运行。

3. 强层级：下一代更会继续改进自己

更强的目标，是让系统更自主地发现能力缺口、选择研究方向、设计实验，并使后继系统成为更有效的改进者。

例如，下一代系统不仅更会玩游戏，还更擅长判断该学习什么、如何获取可靠经验、应该修改哪些组件，以及如何用有限资源验证方案。这些能力又能帮助它研发后续版本。

这里需要证明的是：在可比较的条件和预算下，后继系统比前一代更能产生有效的后续改进。单次任务分数提高，或者成功训练出一个新模型，都不足以单独证明这一点。

层级 改进的重点 关键问题
弱 保留并复用有效经验 这次学到的，下次还能用吗？
中等 修改产生改进的机制 以后能用更好的方法学习吗？
强 增强后继系统的改进能力 下一代能更有效地研发下一代吗？

三、MetaRSI：把自我改进拆成三类工作

一个 Agent 的表现由多部分共同决定。它需要学习数据，需要模型本身的能力，也需要运行时使用的提示词、记忆、工具和技能。这套围绕模型组织工作的运行环境，通常称为 Harness。

MetaRSI 将这些部分作为三类改进对象，由不同角色负责。调度器读取运行反馈，决定先调用哪个组件、让它处理什么问题，以及是否需要继续调用其他组件。

组件 负责的工作 主要产物
Data-RSI 从运行经验中整理、合成并验证学习材料 可复用的数据和经验记录
Harness-RSI 修改提示词、记忆、工具和技能等运行环境 能立即使用的规则、工具或流程
Model-RSI 通过训练调整模型参数等模型状态 能力发生变化的模型

数据、Harness 和模型是三个修改对象，各自都可能参与不同层级的改进。修改了模型参数，也不代表系统就达到了强 RSI。

在论文实验中，分析、提案、调度等由模型执行的角色，都使用被改进的目标模型。同一个底层模型在不同上下文中承担不同职责，使实验能够研究系统自身的改进机制，而不必依靠一个更强的模型来提供方案。MetaRSI 方法部分

四、沿着一次失败，看清三重改进

继续用《我的世界》中的采集任务说明这套机制。下面是帮助理解的简化例子；MetaRSI 论文实际使用的是代码、终端任务和封闭式科学推理等基准。MetaRSI 实验部分

第一重：让 Agent 学会完成任务

Agent 多次采集失败后，系统分析运行记录，发现它没有检查工具的前置条件。一个成本较低的尝试，是先让 Harness-RSI 修改采集技能，补充“检查镐；没有镐时先收集材料并合成”的规则。

修改之后，系统重新运行任务。背包里已经有镐、只有部分材料、完全没有木材时，Agent 都应当采取相应行动。如果新规则在这些场景中有效，就保留这次修改。

随后，Data-RSI 可以整理当前系统的运行轨迹，围绕工具检查、材料收集和合成顺序生成并验证更多学习材料。系统状态已经变化，因此需要使用修改后的新反馈，不能只依赖旧日志。

如果这类行为经常出现，而且有足够可靠的数据，调度器可以调用 Model-RSI，使用 LoRA 等方式微调模型。训练完成后，再检查模型是否已经掌握相关行为；如果减少额外规则后仍然表现稳定，就可以尝试精简技能。

这条路径可以概括为：

数据、Harness 和模型需要根据新反馈交替工作，具体顺序取决于当前问题和成本。某项能力通过技能就能稳定实现时，也可以继续保留在技能库中。

这一轮改进的结果是：Agent 学会了完成采集任务。如果产生改进的流程始终固定，到这里主要体现的仍是弱层级的持久化改进。

第二重：修改产生改进的流程

随着任务增加，Harness-RSI 每遇到一次失败就追加一条规则。技能库逐渐变长，还出现了适用条件不清、前后冲突的问题。

调度器因此修改 Harness-RSI 所遵循的改进流程：新增内容前先查找相关规则，合并重复项，解决冲突，再验证修改效果。

这次修改影响的是后续所有技能更新。原本负责改进 Agent 的机制，现在也得到了改进，因此进入了中等层级所讨论的范围。

第三重：修改安排改进工作的策略

系统进一步发现，每学到一条规则就启动一次训练，会产生大量收益有限的小任务，整个过程又慢又贵。

更高一层的控制角色读取多轮改进记录，修改调度器遵循的策略：先通过技能解决问题，积累经过验证的经验；当某类行为足够高频、稳定，而且值得承担训练成本时，再安排微调。

这次修改会改变后续如何选择和组合改进手段。它比更新单个组件的流程又深入了一层，但仍然属于对改进机制的调整。

因此，**MetaRSI 的三重改进，不能直接对应弱、中、强三个层级。**第一重改变任务能力，第二重改变组件的改进流程，第三重改变调度策略；后两重都可以属于中等层级。

五、为什么还不能直接称为强 RSI

能修改调度策略，说明系统可以调整自身的改进机制。但这并没有自动证明：下一代系统能够在更开放的任务中，自主找到有价值的研究方向，并更有效地继续研发后继系统。

MetaRSI 展示了预设框架内的递归改进机制。按照前面的划分，可以用它理解中等层级的 RSI；要进一步声称具备强层级的能力，还需要验证更广的自主研究能力，以及这种能力能否跨代增强。

同样，让模型自己写训练代码、合成数据，再产出一个新模型，也不意味着这条链路已经完成。新模型可能更会完成任务，却仍然不会挑选更好的数据、设计更好的实验，或者找到值得投入资源的方向。

这里需要分别评估两种进步：任务能力的进步，以及产生后续改进的能力的进步。

后者如果能够持续增强，可能缩短研发周期，让同样的资源产生更多改进；但收益不会因此自动无限增长，数据、算力、实验和验证仍然有成本。

六、怎样判断系统真的变强了

自我改进需要可靠的反馈。让同一个模型写题、作答、打分，并不能保证结果正确；多个角色也可能共享同一种错误认识。

以采集任务为例，验证应该检查 Agent 是否真正获得了圆石，而不是只看它有没有写出一段合理的行动计划。

还需要检查三件事：

  • 新任务上的表现：改进是否能用于没有参与学习的场景，而不是只记住已有样例。
  • 原有能力和总成本：新增能力有没有带来退化，收益是否值得消耗的时间、Token 和训练资源。
  • 后续改进的效率：从相同起点出发、使用相同预算，新改进机制是否比旧机制带来更多有效进步。

评价标准本身也需要受到保护。如果系统可以把“成功采集圆石”改成“找到石头”，更高的成功率就失去了意义。MetaRSI 因此将封闭评估器等对象放在改进机制的修改范围之外。MetaRSI 的评估保护边界

系统还需要获得可靠的新信息。反复整理已有回答，不能保证补上原本缺少的知识；环境反馈、检索资料和真实实验，可能成为下一步进展的来源。MetaRSI 关于能力边界的讨论

RSI 的研究价值，在于把这些反馈持续转化为能力，并让产生能力的过程本身变得更有效。至于它何时能够支持更开放、更自主的智能系统，需要由跨任务、跨轮次和跨代的实验结果来回答。
